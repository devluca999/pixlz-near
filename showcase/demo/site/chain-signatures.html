Chain signatures: one NEAR account, every chain

Explainer · Pixlz demo page (written for the video; not a real publication)

Most people who use more than one blockchain end up with a drawer full of wallets: one for Bitcoin, one for Ethereum, one for each new chain. Chain signatures are NEAR's answer to that drawer.

Signing for other chains

A NEAR account can sign a transaction for Bitcoin or Ethereum without ever holding a private key for that chain. It asks a network of nodes to sign for it, and no single node ever holds the whole key.

Each NEAR account can derive many addresses on other chains, one per path it chooses. The same account always gets the same address for the same path, so it can receive funds there and spend them later.

Why it matters for apps

An app built on NEAR can hold assets on several chains and move them under one set of rules, written once in a NEAR contract, instead of running a separate wallet for every chain it touches.

What it doesn't do

It doesn't make other chains faster or cheaper. A Bitcoin transaction signed this way is still an ordinary Bitcoin transaction, with Bitcoin's fees and confirmation times.
